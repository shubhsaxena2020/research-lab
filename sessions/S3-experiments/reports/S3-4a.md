## Contract compliance (CONTRACTS §2-4)

- Run folder `04_experiments/runs/<UTCstamp>_<config>_<shorthash>/` with
  `meta.json, config.json, stdout.log, stderr.log, results.json, artifacts/`.
- `meta.json` has every required field: `run_id, config_name, config_sha256,
  git_commit, git_dirty, python, platform, command, started_at, finished_at,
  duration_s, peak_rss_mb, device, cpu_count, seed, host, env, notes`
  (+ `experiment`, `status`, `schema`, `toy` when set).
  `git_commit` = real `git rev-parse --short HEAD` via subprocess (`71afecb`
  here); `git_dirty` = non-empty `git status --porcelain`; `peak_rss_mb` from a
  50 ms psutil sampler over process+children, `null` documented when psutil is
  absent (never a fabricated number); `env` records `PYTHONHASHSEED` etc.
- `results.json` = `{"_meta": {...}, flat scalars}`, one nesting level enforced
  by `validate_metrics` (raises on lists / deep nesting / a user `_meta`).
- Provenance integrity: config copied verbatim to `config.json`; its canonical
  sha256 equals `meta.config_sha256` (re-verified for all 6 toy runs in Python).
- Failing `fn`: `meta.json` with `status: "error"` + traceback in `stderr.log`,
  no `results.json`, exception re-raised.
- `RESULTS-INDEX.json` entries: `id/file/key/description/run_id/tolerance`,
  `key = stats.<config>.mean`, written atomically (temp + `os.replace`),
  idempotent, other workers' entries preserved.

## Integration with the other worker's `stats.py`

`stats.py` landed while I was building, exposing `summarise / bootstrap_ci /
paired_test / effect_size / holm` (no `enrich_summary`). `aggregate.apply_stats`
therefore has two tiers: `enrich_summary(summary[, metric])` if ever added,
otherwise it composes the primitives — bootstrap CI per config
(`n_boot=10000, ci_seed=12345`, BCa with percentile fallback, `ci_method:
"bootstrap"`), and one paired block (baseline = first config, Holm-corrected
family, named effect size). Verified end to end: the toy summary now carries
`ci95`, `paired = {sign_test, p=0.5, cohens_d=-2.31, holm p_adjusted=0.5,
family_size=1}` and `tables.py` renders it:
`| toy_ours | 0.8852 ± 0.0064 (n=3) | ... not statistically significant (p = 0.5, sign_test, holm-adjusted...)`.

## Deviations / decisions the lead should know

1. **Same-second run_id collisions** get a `-2`, `-3` suffix (contract format
   otherwise preserved). Six toy runs in ~1.3 s hit this; the seed in
   `meta.json` is the authoritative identity. Documented in the harness README.
2. `meta.json` carries four extra keys (`experiment`, `status`, `schema`,
   optional `toy`) — `aggregate` needs `experiment`, and the toy contract needs
   `toy`. All contract keys are present and unchanged.
3. `aggregate` keeps the **newest** run per (config, seed) and lists the
   superseded ones on stderr, so re-aggregation is stable and never doubles a
   seed.
4. Toy writes 2 `toy.*` entries into `RESULTS-INDEX.json`, flagged
   `"toy": true` + `[TOY - NOT A RESULT]` in the description, so
   `check_numbers.py` can reject them without `--allow-toy`. Delete them or use
   `--no-index` if the lead prefers a clean index before Phase 2.
5. `--check-repro` writes real run folders (legitimate provenance); it is not a
   throwaway mode.
6. `lock.py acquire` from the CLI records the **invoking shell's pid** (override
   `--pid`), because the CLI process exits immediately and would otherwise look
   stale at once.

## Known limits

- No GPU/thread determinism control (record those in the config).
- `--check-repro` compares against run #1, not against a previously archived
  run id (no `--baseline-run` flag yet).
- Aggregate's paired block covers baseline-vs-each-config and reports the first
  comparison in `paired` (all of them in `paired_all`); a multi-metric summary
  is one file per experiment+metric (contract shape).
