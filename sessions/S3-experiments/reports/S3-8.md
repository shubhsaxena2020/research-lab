## What the tool emits

One `06_review/STUDENT-DIGEST/<SECTION>.md` per input, with exactly these H2 blocks:

1. `## What this section says` - one bullet per prose paragraph. The bullet is the paragraph's
   first sentence, stripped of markup/citations, `we/our/us` -> `I/my/me`, cut at 25 words with
   an ellipsis. It is extractive: a test proves every content token in a bullet already exists
   in the draft paragraph.
2. `## Why it is there` - role purpose + paragraph/number/citation counts + a role-specific
   reader checklist (intro / method / results / limitations / related / discussion /
   conclusion / abstract / generic).
3. `## What could be asked at a talk` - 5 prompts for most roles, 6 for results, from a fixed
   per-role bank, each tagged with a real paragraph (or the paragraph holding the number).
   The results bank covers why-this-metric, falsification, seed count, baseline strength,
   ablation, and practical significance.
4. `## Five likely questions with honest answers` - exactly 5, each answer starts with "I".
   Numbers resolve through `RESULTS-INDEX.json` -> `file` -> dotted `key`, and the stored value
   is read back and quoted with the file. Citations resolve through
   `verified_citations.csv` and are quoted as title/venue/year. Unresolvable evidence produces
   `[TO FILL: ...]`, never a value.
5. `## Glossary` - technical terms outside a small built-in BCA vocabulary, each as
   `**term** — [TO FILL: define it in my own words ...] (first appears: paragraph N; k mentions)`.
   No definition is ever generated.

Extra honesty guards: the digest flags a draft/index mismatch with `[TO FILL]`; refuses to
quote entries marked `"toy": true` or files under `04_experiments/toy/`; reports an absent
index or citations file as an explicit gap.

## CLI

```
python tools/make_digest.py --section 05_paper/draft/method.md
python tools/make_digest.py --section 05_paper/draft --all
python tools/make_digest.py --check 06_review/STUDENT-DIGEST/METHOD.md [--strict]
```

Exit codes: 0 pass, 1 findings, 2 usage. `--json` is machine-readable. `--role` overrides
filename inference; an unknown filename is `generic` plus a `[TO FILL]` asking for its role.

`--check` verifies: all five blocks present once and in order; >=1 bullet and every bullet
<=25 words; >=3 checklist items; 3-6 talk prompts; exactly 5 questions numbered 1..5 with
first-person answers; every glossary entry is a placeholder, not a definition; and, under
`--strict`, zero `[TO FILL]` remain.

## Known limits (honest)

- No real draft section exists yet (`05_paper/draft/` is empty), so the tool has not been run
  against the actual paper. It degrades to visible `[TO FILL]` when the real index/citations
  files are missing or lack an id/key.
- Glossary recall is lexicon + acronym + `-isation/-ization` based. It will miss bespoke
  jargon outside that list; it will not invent a definition for anything it does catch.
- `--check` is structural. It proves the digest is complete and placeholder-only where
  required, not that the student's filled answers are correct.
- "One page" is a design target, not enforced by a page counter. Generated digests are
  ~4-6 KB; a section with many paragraphs or terms will run longer.
- Role inference is filename-based; a misnamed file needs `--role`.
