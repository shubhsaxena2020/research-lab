## API contract notes
- `bootstrap_ci` returns a dict: `lo, hi, method, n_boot, seed, alpha, statistic, n, point, notes` (+ `bca_z0`, `bca_acceleration` for BCa). CONTRACTS §4 needs `n_boot`, `ci_seed`, `ci_method` — all present.
- `paired_test` returns `test, statistic, p_value, n_pairs, n_eff, n_zero, method_detail, notes, correction`. All-zero differences → `{"test": "none", "p_value": None}` with an explicit note; never a fake `p = 1`.
- `effect_size` always names itself (`name`), and every effect size carries `ci95, ci_method, n_boot, seed`.
- `holm` / `benjamini_hochberg` return `method, family_size, p_adjusted, p_raw`.
- `tables.ablation_table` accepts the CONTRACTS §4 single-metric shape, the multi-metric `{metric: {config: [...]}}` shape, `per_metric` / `metrics`-dict blocks, and flat `cells`. It also consumes `paired_all` (written by `aggregate.py`) and picks the comparison that actually covers best-vs-second.

## Validation evidence (all executed, not asserted by eye)
- Wilcoxon exact, n = 6 all-positive: **p = 2/64 = 0.03125** (DP over rank sums, 64 arrangements); one rank-1 negative → 4/64 = 0.0625; n = 9 all-positive → 2/512.
- 255 random untied samples, n = 4…20: exact p identical to `scipy.stats.wilcoxon(method="exact")` within 1e-10.
- 5 × n = 3…9 tied integer samples: sign-flip enumeration identical to an independent `itertools.product` brute force (0 mismatches).
- Tie-corrected normal approximation (n = 30, 17 distinct |d|) matches `scipy ... method="approx", correction=False` to 1e-14.
- BCa matches `scipy.stats.bootstrap(method="BCa")` on two samples (exact match on one; the other differs only by Monte-Carlo noise in the tail).
- Holm/BH asserted against hand-derived values; BH also matches `scipy.stats.false_discovery_control`.
- End-to-end bridge run: `aggregate.apply_stats(summary, "accuracy", stats)` → `tables.ablation_table(...)` renders, and `aggregate`'s own `test_apply_stats_hook_uses_real_stats_module` passes against this module.

## One deliberate deviation from the task text
The brief said Holm on `(0.01, 0.02, 0.03)` gives `0.03, 0.04, 0.03`. That is the raw step-down product; it is **not** a valid Holm adjustment because adjusted p-values must be monotonically non-decreasing in sorted order (R `p.adjust(..., "holm")` and statsmodels both enforce it with a running maximum). The correct value for the third test is **0.04**, so the implementation and test assert `[0.03, 0.04, 0.04]`. Returning 0.03 would claim the weakest test is more significant than a stronger one. If the lead wants the naive value, that is a one-line change in `holm()` — but it would be wrong and a statistician reviewer would catch it.

## Caveats the paper must keep
- n = 5 seeds: the bootstrap has only 126 distinct resamples, so CIs are indicative; `summarise` and the table generator both warn at n < 5 (and n = 5 is the floor for any two-sided paired test to reach p < 0.05 at all: min p = 2/2⁵ = 0.0625).
- Welch/paired tests here are two-sided and assume paired, independent seeds; `auto` picks the sign test below 6 pairs and says so rather than pretending Wilcoxon is informative there.
- Effect sizes on bounded metrics (accuracy near 1) are not comparable across datasets — report the raw delta too.
- `aggregate.py` currently passes raw `p_value` with `p_adjusted: null`; the table then labels it "unadjusted p" and raises a warning instead of calling it corrected.
