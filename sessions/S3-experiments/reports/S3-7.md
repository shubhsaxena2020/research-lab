# S3-7 — claims audit: template + validator

Date: 2026-11-03. Owner: S3-7. Status: **done, tests green**.

## What this is for

RULES.md #2 and #5 say every number comes from a result file and no "state of the art" ships
without a novelty check. Those rules were prose. This package turns them into a table that a
reviewer signs and a script that re-checks the table from disk.

Invocation (as specified):

```
python tools/claims_audit.py --audit 06_review/CLAIMS-AUDIT.md \
  --draft 05_paper/draft/ --index 04_experiments/RESULTS-INDEX.json \
  --citations 02_literature/verified_citations.csv
```

## What the validator actually checks

Row level, each independent of the others:

- `evidence_file` exists (relative to `--root`, else relative to the audit file).
- `evidence_key` resolves in that file: dotted JSON path (`paired.p_value`, `_meta.n`, list
  indices as `[i]`); `column=value` for CSV (default value column `status`); literal phrase for
  `.md`/`.txt`.
- stored value vs `result_value`: numeric with tolerance (index entry `tolerance` = relative,
  else 1% relative; a trailing `%` is converted, so `86.5%` matches `0.865`); strings
  case/whitespace-insensitive; for text evidence the printed quote must occur in the file.
- citation keys cited by the row (`[@key]`, `\cite{key}`) must be in `verified_citations.csv`
  with status `VERIFIED` — `MISMATCH` is a fail.
- `verified` must be exactly `YES`; missing required fields fail the row.

Draft level:

- abstract + introduction of every `.md`/`.tex` under `--draft` are split into sentences
  (decimal points are not sentence breaks; citation-key years are not claims);
- every sentence with a digit or a comparative stem must match a row's claim text at
  >= 0.80 (Dice token overlap, or containment when the shorter side has >= 5 tokens);
  unmatched sentences are reported `UNCOVERED` with `file:line`;
- `state of the art` / `novel` / `first` must have a matching row whose `evidence_file` is
  `NOVELTY-CHECK.md`, else `NOVELTY_ROW_MISSING` at `file:line`. Enumerative "First, we ..."
  is exempt; this is documented in the template.

Rows with `claim_id` starting `EX-` are skipped entirely: not judged, not used for coverage, and
counted separately (`n_rows_skipped_examples`). That is what lets the shipped template contain
deliberately incomplete examples without blocking anything.

## Judgement calls worth knowing

- **Verbatim or nothing.** Coverage is textual on purpose; a paraphrased claim is reported
  `UNCOVERED` even if the evidence exists. The template says quote, do not paraphrase.
- **One row binds one number.** A sentence printing two numbers needs two rows. The tool does
  not reconcile every digit inside a row's claim; the reviewer does, and splitting keeps that
  possible. Documented as a known limit rather than hidden.
- **0.80 threshold.** Verbatim scores 1.0; a paraphrase of one clause usually lands 0.55-0.75.
  Boilerplate ("we evaluate ... on ... queries") can inflate the score against the wrong row, so
  the template asks the reviewer to eyeball `covered_by`.
- **`01` gap.** On the current repo the documented command exits 2 because
  `06_review/CLAIMS-AUDIT.md` and `05_paper/draft/` do not exist yet (Phase 2 is locked). That
  is correct behaviour, not a defect: the tool refuses to audit a missing file.
