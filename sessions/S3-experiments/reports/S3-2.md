Status: **DONE**. 46 tests pass. Tool runs, exits 0/1/2 as specified, writes the Markdown report.

## What it does

Scans a draft (`.md` / `.tex`, file or directory tree) and finds **every** numeric token —
`0.812`, `12.3%`, `1,234`, `3.5x`, `+2.1`, `3e-4`. Each token is then classified:

| status | meaning |
|---|---|
| `MATCH` | inside a `num:` marker whose id exists in `RESULTS-INDEX.json` **and** whose printed value equals the value at `key` in `file` (percentage and rounding allowed) |
| `EXEMPT` | one named, narrow rule says it is not a result (year, `[12]`, DOI, arXiv id, figure/table/eq. number, p./line, URL, LaTeX ref/label/cite arg, LaTeX dimension, list marker, ISO date, or an explicit `--exempt` pattern) |
| `UNTRACEABLE` | neither of the above → **finding** |
| `MISMATCH` | marked, but printed value disagrees with the stored value → **finding** |
| `DANGLING_MARKER` | marker id absent from the index → **finding** |
| `INDEX_ERROR` | id exists but its file/key is missing or non-numeric → **finding** |
| `UNBOUND_MARKER` | a marker that wraps no number (stale receipt) → **finding** |

Exit codes: `0` clean, `1` any finding, `2` usage error (missing draft/index, malformed JSON,
bad regex in the exempt config, `--context < 0`, unsupported file type).

Outputs: Markdown report (default `06_review/numbers-audit.md`, override with `--out`, skip
with `--no-write`), `--json` to stdout, `--json-out PATH` to a file.

## Decisions the lead should know about

1. **Tolerance is read both ways.** `CONTRACTS.md` §3 calls `tolerance` *relative*; the brief
   says `max(tolerance, half of last printed decimal place)`. Both are honoured:
   `allowed = max(|tol|, |tol|*|stored|, half_ulp)`. With the default `tolerance: 0.0` only
   the rounding window applies, which is the normal case. Evidence in the report always
   prints the three components, so a loose entry is visible.
2. **Toy detection is stricter than the brief.** An entry counts as toy if its `file` path
   contains `04_experiments/toy/`, **or** the index entry carries `"toy": true`, **or** the
   results file itself carries `"toy": true`. The real `RESULTS-INDEX.json` (written by the
   harness worker) marks toy entries with the flag while pointing at
   `04_experiments/results/summary_toy.json`, so a path-only rule would have let toy numbers
   through. `toy_flag` / `toy_file` fixtures pin both extra cases.
3. **Two statuses beyond the brief** (`INDEX_ERROR`, `UNBOUND_MARKER`) are findings, not
   crashes: an index entry pointing at a missing file, or a marker left behind by a deleted
   number, is a real defect and must fail the run.
4. **Index `file` resolution**: repo-root first (as documented), then the index file's own
   directory. The fallback exists only for self-contained fixture/mini-repos; both attempted
   paths are reported in the error when neither exists.
5. **Config patterns are position-checked**: a `--exempt` regex only exempts a number when
   the regex match covers that number's characters. A pattern for `learning rate 3e-4` cannot
   accidentally excuse a metric on the same line (tested in
   `ExemptionTests.test_config_pattern_only_exempts_what_it_covers`).

## Known limitations

- **The year rule is a hole by design.** A bare 4-digit number 1900–2100 is treated as a year.
  If a count or metric is exactly such a number (e.g. "2000 iterations"), it is silently
  exempt. Mark it if it matters. This is what the brief asks for.
- **Half-ULP applies to integers too.** `5` matches a stored `5.4` (half of the last decimal
  place of `5` is `0.5`). Consequence of the stated rounding rule, not an extra allowance.
- **Glued digits are invisible.** The tokeniser deliberately skips numbers attached to a word
  (`ResNet50`, `v1.2.3`, `Fig.3`), because those are identifiers. Under-detection, not a false
  alarm; `GPT-4`, `ResNet-50`, `top-1` are handled by the `identifier_attached` rule.
- **Multi-number lines in LaTeX are ambiguous.** A `% num:id` comment binds the *nearest*
  preceding number (trailing comment) or the *first* number on the next line; any other number
  on that line stays untraceable and is flagged. Deliberate: ambiguity is reported, not
  guessed. One number per marked line is the rule.
- **Not exempted on purpose**: GPU counts, parameter counts, training hours, `p < 0.05`
  thresholds, run counts ("3 seeds"). These are claims and should be marked (they exist in
  `meta.json` / `results.json`), or named in `exempt_numbers.json` if the lead decides they
  are protocol constants.
- The unterminated `<!-- comment` case is not masked, so numbers inside it are flagged. A
  broken comment is a broken draft; left as-is.
- No network, no writes outside the repo, no dependency outside the stdlib.
