### 2.7 Compatibility with the *real* harness output

Another worker landed `04_experiments/RESULTS-INDEX.json` and
`results/summary_toy.json` mid-build. Tested against them:

* `--figure main-accuracy` → exit 2, "no index entry matches", and it lists the
  ids that do exist (`toy.accuracy.toy_baseline`, `toy.accuracy.toy_ours`).
* `--figure toy` without `--allow-toy` → exit 2: `index entry
  'toy.accuracy.toy_baseline' is marked toy=true ...`.
* `--figure toy --allow-toy` (smoke test, output written to `C:/tmp` and
  discarded) → 2 values read through the real dotted keys
  (`stats.toy_baseline.mean`), CSV/SVG/TeX written. So the parser handles the
  harness's actual `id`/`key`/`file`/`toy` fields, including `toy` at the *entry*
  level, which the contract does not spell out.
* `tables/make_tables.py --summary 04_experiments/results/summary_toy.json` →
  exit 2 (toy).

This also caught a real bug: `build.sh` passed MSYS paths (`/c/Users/...`) to
native `python.exe`, which resolved them as `C:\c\Users\...`. Fixed with a
`cygpath -w` helper. Worth knowing for any other shell script that calls python.

### 2.8 The SVG is a chart, not just well-formed XML

The test only proves the SVG parses. To check it actually *reads* as a figure,
it was rasterised with ImageMagick and inspected:

```
$ magick main-accuracy.svg check.png     # ImageMagick warns about the font stack, renders anyway
$ magick stress.svg stress.png           # 8 bars, long labels, one negative value
```

Render 1: title, two bars (`baseline` 0.812, `ours` 0.91), y axis 0–1 with
0.2 ticks, axis titles, value label above each bar, no clipping.
Render 2 (stress): long labels wrap and truncate with an ellipsis instead of
overlapping; the negative bar sits below a drawn zero line with its label below.
Known cosmetic issue: plotting metrics with wildly different units on one axis
(e.g. `train_time_s = 240` next to `accuracy = 0.41`) squashes the small bars —
that is the author's choice of metrics, not a renderer bug, and the generator
does not silently rescale to hide it.

## 4. Limitations (do not paper over these)

1. **No compilation.** No `pdflatex`/`latexmk` on this machine, so no PDF exists
   and no claim is made that `main.tex` typesets. The tests verify structure
   (braces, environments, ref/label wiring) — they cannot catch a bad package
   option, a missing `\RequirePackage`, or a float that will not fit.
   `BUILD.md` says this in its "Verified status" section.
2. **No PDF figures.** matplotlib is absent, so figures are CSV + SVG + a
   placeholder box. The `.tex` fragment includes the PDF automatically once it
   exists; nothing else needs editing.
3. **IEEE/ACL formatting is untested** against the real style files, which are
   not in the repo and must not be. `IEEEtran.cls` is also not installed, so
   `--venue ieee` has never run.
4. **`refs.bib` is empty by design**, so `\bibliography{refs}` will emit
   "no \citation" warnings. Expected, not an error.
5. **The `num:` markers in `DRAFT.md` are placeholders** (`main.accuracy.ours`
   etc.) and will fail `tools/check_numbers.py` until real ids exist. That is
   the intended failure mode.
6. **`\fillme{}` boxes and `TODO(...)` comments are everywhere.** `grep -rn
   "TODO("` must come back empty before anything is called a draft.
7. `build.sh` was exercised only on git-bash/Windows. The POSIX paths are
   ordinary, but it has not run on Linux or macOS.
