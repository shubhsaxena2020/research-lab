# MF-10 — answerability adjudication (R3-3b)
**Post-hoc / exploratory.** Repeated LLM judgement on the existing seeded 100-item negative sample; not human gold. Does not change any pre-registered verdict.
## Design
- Sample: `04_experiments/results/c1/r3/exp/adjudication/sample.csv` (exact, no resample), 100 seeded negatives, 25 per rung 1-4, seed 20261103, 48 dev / 52 test.
- Annotators: A = qwen2.5:1.5b-instruct; B = qwen3:1.7b (think=false); resolver = qwen3:1.7b (strict). Temperature 0, format=json, Ollama http://127.0.0.1:11434.
- Rubric: `mf10_rubric.md` (copy of source rubric; sha256 15419fe5d47d43b42641a6c66ab6b0735f4a2e3dde41e9f96db644c38b7423aa).
- GPU-first: Ollama llamacpp on Intel Arc 130T iGPU Vulkan (OLLAMA_IGPU_ENABLE=1); CPU fallback reason = null. size_vram A=1367049502, B=2243680009, resolver=2243680009.

- Disagreements = 41.

- Resolved answerable = 56/100 (56.00%).

## Comparison with prior LLM adjudication
- Prior: `04_experiments/results/c1/r3/exp/adjudication/adjudication.json` (kappa=0.1975, A share=0.3, B share=0.06, resolved share=0.05, resolved n=5).
- Present re-derivation: kappa=0.2802, A share=0.62, B share=0.21, resolved share=0.56 (n=56). The resolved estimate differs sharply from the prior strict-resolver estimate (5/100); this is a prompt/model sensitivity finding, not a correction.
- Present run re-derives labels with GPU-first Ollama provenance and a qwen3:1.7b strict resolver; compare cautiously. Both are LLM judgements, not human gold.

## Limitations
- LLM annotators, not human gold standard; n=25 per rung; post-hoc/exploratory.
- Resolver may share model-family bias; recorded raw responses allow audit.
- In this run the resolver sided with A on 35/41 disagreements and with B on 6/41; it therefore raised the resolved answerable share far above the prior strict-resolver result. Treat the resolved numbers as one LLM judgement, not a stable gold estimate.
- No CPU fallback occurred; the Ollama llamacpp backend served all generation on the iGPU Vulkan device.
